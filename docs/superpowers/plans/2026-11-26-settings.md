# Settings and Reminders Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Settings sheet, opened from Apartments, turns on a month-end reminder at a chosen time; the reminder
arrives on the last day of a month with a cleaned apartment and opens that month's report.

**Architecture:** Pure domain values (`ReminderTime`, `MonthEndReminderSettings`, `MonthEndReminder.next`) in
`Models/Reminder/`; a `SettingsRepository` (fake + `UserDefaults`) streams the settings; `MonthEndReminderScheduler`
(`App/`) keeps one pending notification in step with the settings and the current month through a `ReminderCenter`
protocol; `SettingsViewModel` handles the switch, the time and the permission through `NotificationPermission`;
`SystemNotifications` (`App/`) is the only `UserNotifications` code besides `ReminderResponder`, which turns a tap
into a report request that `RootView` presents.

**Tech Stack:** SwiftUI, UserNotifications, Swift Testing, String Catalog with generated symbols. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-26-settings-design.md` (product spec: Settings).

## Global Constraints

- iOS 18.0+, Swift 6, default `MainActor` isolation; every type in `Models/` is `nonisolated`. Anything else
  `nonisolated` (the delegate methods, the payload parser) carries its reason in the commit message.
- `UserNotifications` and `UIKit` appear only in `App/`; view models import Foundation and Observation only.
- The reminder is **off by default**, its time starts at **18:00**, and it fires on the month's **last day**.
- The fire date is `DateComponents` with year, month, day, hour and minute only — no time zone, no calendar.
- One pending request, identifier `"month-end-report"`; scheduling replaces it.
- Every user-facing string is a catalog key with Ukrainian and English (table in Task 3, 5 and 6).
- Tests pin `now`, `Calendar` (`.warsaw`) and `Locale` (`uk_UA`, one `en_US` case per string builder); no
  sleeps, gates instead.
- No comments in Swift; one argument per line for 3+ arguments; `swift-format lint --strict` clean.

## Review Focus

- The permission revoked in iOS after the reminder was turned on, then Settings opened → the stored «on» stays
  (Task 5 test `openingWithRevokedPermissionKeepsTheReminderOn`).
- The reminder turned off while a request is still being added → nothing stays pending (Task 4 test
  `latestStateWinsOverARequestBeingAdded`).
- A tick on the last day after the reminder time → no request for a moment in the past (Task 1 test
  `noReminderOnceTheMomentHasPassed`, Task 4 test `cancelsOnceTheMomentHasPassed`).
- A trip to another time zone → the reminder still fires at the chosen local time (Task 3 test
  `fireDateHasNoTimeZone`).
- Unreadable stored settings (an older format) → the default, off, not a crash (Task 2 test
  `fallsBackToTheDefaultOnUnreadableData`).

## Plan review (2026-11-26, folded in below)

- `swift-concurrency-pro`: one unstructured `Task` per settings or day change would let an older `add` land after
  a newer removal — the scheduler serializes through a main-actor flag loop that re-reads the latest state after
  every `await` (Task 4). The delegate callbacks may arrive off the main actor, so they are `nonisolated async`,
  parse the payload into a `Sendable` `MonthKey` first and only then call the main-actor `open(_:)` (Task 7); no
  isolated conformance. `schedule` failures go through `do/catch` and `Logger`, never `try?`. The latest-wins test
  uses a gated fake, not a sleep. A thrown `requestAuthorization` counts as a refusal (logged).
- `swiftui-pro`: no `Binding(get:set:)` for the switch and the picker — the view binds `@Bindable` properties and
  calls the view model from `onChange`; the view model ignores a change equal to the stored value, so a stream
  update or a revert never writes back (Task 5). The system-settings row is a `Link`, not an `openURL` closure.
  The version is the last section's footer, not a row. A tap that cold-launches the app sets the request before
  `RootView` exists, so `RootView` reads it with `onChange(of:initial: true)` (Task 7). The sheet keeps the
  default large detent.

**Interfaces:**

- Produces:
  - `@MainActor final class MonthEndReminderScheduler` — `init(settings: any SettingsRepository, workDays: any
    WorkDayRepository, center: any ReminderCenter, now: @escaping () -> Date = Date.init, calendar: Calendar =
    .current, locale: Locale = .current)`; `func observeSettings() async`; `func observeDays(in month: MonthKey)

Each loop stores its latest value and calls one private `reschedule()`, serialized so an older `add` can never
land after a newer state:

```swift
private func reschedule() async {
    needsReschedule = true
    guard !isRescheduling else { return }
    isRescheduling = true
    defer { isRescheduling = false }
    while needsReschedule {
        needsReschedule = false
        await applyLatestState()
    }
}
```

`applyLatestState()` computes `MonthEndReminder.next(…)` from the stored state and `now()`, then
`center.schedule(ReminderRequest(…))` in `do/catch` (logged) or `center.cancelReminder()`.

asking. A failed save sets `errorMessage` and the bound values return to the stored ones.

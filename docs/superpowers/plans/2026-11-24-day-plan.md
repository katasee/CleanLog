# Day plan Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A sheet that adds template apartments (not yet on the day) to any day, with search, «Нова» and
one confirm write, opened from the empty day and from a «+ Додати квартиру» row on the day's list.

**Architecture:** `DayPlanViewModel` (owned by the sheet) observes the template and the day, holds the
selection and the search, and writes once on confirm through `WorkDayRepository.update` with
`WorkDay.planning(_:)`. The apartment form moves to its own feature folder so Apartments and DayPlan
share it; it reports the apartment it created through a callback. `DayView` only presents the sheet.

**Tech Stack:** SwiftUI, Swift Testing, iOS 18.0+, Swift 6 with default `MainActor` isolation.

**Spec:** `docs/superpowers/specs/2026-11-24-day-plan-design.md`

## Review Focus

1. A «Нова» apartment selected before the template stream delivers it: it must count once it arrives and
   be planned on confirm (Task 2 test `newApartmentIsSelectedOnceItArrives`).
2. A selected apartment deleted from the template while the sheet is open must not be planned or summed
   (Task 2 test `deletedApartmentLeavesTheSum`).
3. A selected apartment hidden by the search still counts and is planned (Task 2 test
   `searchKeepsHiddenSelection`).
4. A double tap on confirm writes once (Task 3 test `secondConfirmWhileSavingDoesNothing`).
5. A failed write keeps the selection and shows the error (Task 3 test `failedSaveKeepsTheSelection`).

**Interfaces:**
- Consumes: Task 1's `ApartmentFormViewModel` init.
- Produces:
  ```swift
  struct DayPlanTile: Identifiable, Equatable { let id: UUID; let name: String; let priceText: String; let isSelected: Bool }

  @Observable @MainActor final class DayPlanViewModel {
      init(
          day: DayKey,
          today: DayKey,
          apartments: any ApartmentRepository,
          workDays: any WorkDayRepository,
          calendar: Calendar = .current,
          locale: Locale = .current
      )
      let title: String
      var searchText: String
      var newApartmentForm: ApartmentFormViewModel?
      private(set) var tiles: [DayPlanTile]
      private(set) var selectedCountText: String?
      private(set) var confirmTitle: String
      private(set) var emptyMessage: String?
      var canConfirm: Bool { get }
      func toggle(_ id: Apartment.ID)
      func startNewApartment()
      func observe() async
  }
  ```

State: `template: [Apartment]` (stream order is already `ApartmentNameOrder`), `plannedIDs: Set<UUID>`
(the day's `entries.map(\.apartmentID)`), `selectedIDs: Set<UUID>`. **Selection is never pruned**: what
counts is `chosen = template.filter { selectedIDs.contains($0.id) && !plannedIDs.contains($0.id) }`, so a
deleted apartment drops out and a «Нова» one counts as soon as it arrives. `tiles` = template minus
planned, filtered by `searchText` (trimmed; empty matches all; `name.range(of:options: .caseInsensitive)`).
`emptyMessage`: template empty → `.template`; nothing left after planned → `.allPlanned`; nothing after
the search → `.noMatch`; else `nil`. `confirmTitle`: `chosen` empty → `dayPlan.action.none`, else
`dayPlan.action.add(chosen.count, MoneyFormat.string(sum, locale:))`. `startNewApartment()` sets
`newApartmentForm` with `suggestedName: tiles.isEmpty ? trimmed search : ""` and
`onAdd: { [weak self] in self?.selectedIDs.insert($0.id) }` — weak, because the view model holds the form
that holds the closure (plan review).

Tests (template 100 · 28 zł, 101 · 28 zł, 106 · 56 zł; day `today` with 100 planned; `uk_UA`, `.warsaw`;
an `observing` helper like `DayViewModelTests` waiting until `!tiles.isEmpty || emptyMessage != nil`):
